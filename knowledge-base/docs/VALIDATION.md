### 部署问题及已采用的修复

1. apt/pip 下载慢：区分依赖构建与权重下载；手册补充构建前使用 tmux。当前 pip RUN 未完成时中断可能重下该层依赖，不能承诺保留所有下载进度。
2. Hugging Face 官方站及镜像连接超时：在可联网电脑下载固定版本完整目录，再上传服务器；配置离线挂载，跳过服务器 download-model。
3. 密钥引用：models.json 使用 `${KB_LLM_API_KEY}`，真实密钥存入同级项目根 `.env`，两个角色的 provider/model 对齐配置。
4. Pi 通用配置报错：诊断得到 EROFS 创建 auth.json.lock 失败。compose.yaml 取消 config 的 :ro，目录 GID 1000、权限 770，文件组可读；重新创建 api/worker 后完成正常流程。该修改已在本机通过 YAML merge 解析检查。
5. 重启后模型无法识别：实际挂载只有 model-data 到 /models，而服务器离线文件存在。把 COMPOSE_FILE 与 BGE_MODEL_DIR 写入 `.env`，清除终端临时覆盖值，重新创建 embedding/api/worker，用户确认持久化通过。
6. memory.peak 不可用：读取 Docker 同期采样并标明统计口径与局限，不将采样值称为完整内存峰值。

可复制命令已写入 [运行手册](RUNBOOK.zh-CN.md)；此次仅更新文档，无新增真实服务调用或 pipeline 代码变更。
